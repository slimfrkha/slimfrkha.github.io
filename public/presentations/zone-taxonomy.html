Pages of one site share its templates: they differ only locally (content, a block or two). The big differences are between sites.

The modeling solution · Design choices

Two choices that shape the solution

1 · What should the model read?

Hand-crafted features

✓ simple, interpretable

✗ tied to the label set, slow to explore

✗ the problem outgrows the features

Computer vision on screenshots

✓ strong pretrained backbones

✓ detection / segmentation models

✗ rendering cost; zone boxes are already known

chosen

The HTML itself, as text

✓ independent of the label set

✓ no rendering needed

✗ a model to craft from scratch

2 · What should it predict?

One zone at a time

✓ simpler modelling and training

✗ no access to parents or neighbours

✗ which snippet: with or without children? Labels differ from user annotations

chosen

Every node of the page at once

✓ sees parents and children; each node keeps only its own HTML

✓ training labels = user annotations

✗ page batching, dynamic tree graphs, long gradient paths

→ Read each node's own HTML, and classify all the nodes of the page together along the DOM tree.

Modeling deep dive · 1 Node encoder

One signal, end to end: a character CNN

Same recipe for every signal. Markup and attributes use k = 3, 5, 7, 9; id, class and text use k = 3, 5. Text starts from 768-d BERT word-piece vectors instead of 8-d character embeddings.

markup 64 id 64 class 64 attributes 64 text 64 →dense · dropout 0.3→64-d local vector
Zone TaxonomyModeling: node encoder
Modeling deep dive · 2 Tree context · first version

A node is understood by its surroundings

Based on the Child-Sum Tree-LSTM: K. S. Tai, R. Socher, C. D. Manning, Improved Semantic Representations From Tree-Structured Long Short-Term Memory Networks, ACL 2015, arXiv:1503.00075.

Child-sum TreeLSTM: each node combines its own local vector with the summed states of its children, using forget gates per child.

↑

Upward pass computes nodes level by level by height: all leaves at once, then their parents, … up to the root.

↓

Downward pass runs a second TreeLSTM from the root, fed with the upward states, with a residual memory link.

node = [ local (64) ‖ h↑ + h↓ (64) ] → 128-d

A price node now knows it sits under a product block, next to a title and a button.

First version. Replaced by masked tree attention: next slide.

Zone TaxonomyModeling: tree context
Modeling deep dive · 2 Tree context · current version

From TreeLSTM to tree attention

The TreeLSTM runs one step per tree level, twice. Masked attention updates every node at once: parallel and much faster on GPU. Context is still taken in two directions, as two attention tracks:

↕

Branch track (vertical). A node attends to its ancestors and descendants within a hop limit: 6 hops in the real model (1 in this illustration). Farther ones are masked; they don't help the decision.

↔

Sibling track (horizontal). A node attends to the other children of its parent: what sits next to it.

softmax( QKᵀ/√d + M ) V  ·  M = 0 kept, −∞ masked

Real model: two stacked layers bring in first-degree cousins: in layer 1 the grandparent gathers its descendants, in layer 2 the node reads its grandparent. Heavily inspired by TrENC, not identical (±6-hop branch, 2 layers).

Based on TrENC: Li et al., Extracting Shopping Interest-Related Product Types from the Web, arXiv:2305.14549 (2023): path + sibling attention on DOM trees.

Zone TaxonomyModeling: tree attention
Modeling deep dive · 3 Decision

One head per page category

Each head is small: Linear → sigmoid → Linear → softmax over that page category's zone list.

The page category is an input: it selects which head answers, so a product page can never be given a checkout-only zone.

All page categories share the encoder and the tree-context block, so knowledge transfers across page types.

In training, the loss is masked per head: each node only trains the head of its own page category.

Zone TaxonomyModeling: decision
Modeling deep dive · Training

Learning when 96% of nodes are background

Focal loss

−y · log p · (1 − p)γ, γ = 2

Easy, confidently-correct nodes (most "others") contribute little; the hard ones drive learning.

Prior-aware start

softmax(bias) = others share

Output biases are initialised so the untrained model already predicts "others" at its true frequency, so no wasted early epochs.

Page-category weights

w = max count / count

Page types with fewer training nodes weigh more in the loss.

Invisible nodes give context, not loss

Fully invisible subtrees are removed. Remaining invisible nodes still pass through the tree model but are masked out of the loss and metrics.

One page per step, 16 accumulated

Adam (lr 3·10⁻³), learning rate halved on plateau, early stopping on validation F0.5.

Zone TaxonomyModeling: training
Modeling deep dive · Granularity

"Nearly right" is a real situation

One price on screen, three nested nodes, one annotation: by rule, the biggest node holding only the zone. If the model answers one level in, it still found the zone.

The near-zone idea is used in three places:

Training · near-zone soft labels

Don't punish the model hard for the levels next to a zone; teach how likely each one is to be the zone.

Evaluation · near-zone tolerance

Score the zone as found when the prediction lands one level off, and count each zone only once.

Serving · grouping

Return one node per nested cluster, with the others listed as synonyms.

Granularity · Evaluation

An evaluation that measures "zone found"

1

Split by website. No domain is in both train and validation (no template leakage), so the score is about unseen websites. Each (page, zone) pair keeps a ≈75/25 split (±15%).

2

Group predictions like serving does: one node per same-label nested cluster (≤ 8 hops, ≤ 2 extra branches).

3

Near-zone swap. A zone predicted "others" whose neighbour (≤ 3 hops) was predicted with that zone swaps labels with it: the zone counts as found once.

4

Score F0.5 per zone (precision-weighted), averaged over the zones of each page category, then over page categories. This score selects checkpoints and stops training.

Recap

Zone Taxonomy in four ideas

1

Read every node

Character CNNs over markup, id, class, attributes, plus text.

2

Use the whole tree

Masked tree attention along branches and siblings: what's inside, where it sits.

3

Respect the page type

One head per page category, one shared backbone.

4

Near-zone aware

Soft labels to train, tolerant scoring to evaluate, grouping to serve.
